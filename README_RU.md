# FormTest — Фреймворк для тестирования способности ИИ анализировать структурированные форматы

> **Прилагаемые тестовые наборы являются вымышленными данными, сгенерированными ИИ, а не реальными данными. Любые совпадения случайны.**
>
> **Данный проект не прошёл надлежащую сборку и планирование тестирования; структура кода и тестовое покрытие ещё не завершены. Предназначен только для ознакомления и обучения.**

Автоматизированный фреймворк для оценки способности больших языковых моделей (LLM) понимать и анализировать структурированные форматы данных. Он автоматически вызывает AI API через предопределённые тестовые сценарии, сравнивает возвращаемые результаты с ожидаемыми ответами и количественно оценивает производительность модели в понимании форматов.

## Быстрый старт

### 1. Установка зависимостей

```bash
pip install -r APPs/requirements.txt
```

### 2. Запуск

```bash
cd APPs
python app.py
# Или дважды щёлкните run.bat
```

Откройте браузер по адресу [http://localhost:5000](http://localhost:5000)

### 3. Настройка

После запуска нажмите кнопку **Настройки** в правом верхнем углу веб-интерфейса, чтобы настроить адрес API, модель, параметры и т.д. Также вы можете создать файл конфигурации, используя `APPs/config.example.json` в качестве образца.

Основные параметры настройки:
- `base_url` — Адрес API (поддерживается автоматическое добавление `/v1`)
- `model` — Имя модели по умолчанию
- `model_thinking_config` — Конфигурация режима рассуждения/размышления по моделям
- `streaming` — Переключатель потокового вывода SSE
- `concurrency` — Количество параллельных потоков
- `disabled_params` — Параметры, скрытые/отключённые в интерфейсе

### 4. Запуск тестов

1. На **холсте** с помощью редактора узлов скомбинируйте: промпт × вопрос × модель
2. Нажмите **Начать тестирование** для просмотра потоковых результатов в реальном времени
3. После завершения теста просматривайте/фильтруйте результаты в **Истории результатов**

## Тестовые наборы

### Структура

Каждый тестовый набор использует файлы-маркеры `.test-set-part` для определения роли поддиректорий. Имя директории может быть произвольным; система распознаёт их по содержимому маркерного файла:

```
Benches/<имя>/
├── <директория вопросов>/         # Содержит .test-set-part → "questions"
│   ├── .test-set-part
│   ├── 基础问题.json              # 10 вопросов
│   └── 进阶问题.json              # 10 вопросов (в некоторых наборах только базовые)
├── <директория промптов>/        # Содержит .test-set-part → "prompts"
│   ├── .test-set-part
│   ├── <имя>原版.json             # Текстовый повествовательный формат
│   ├── <имя>列表.json             # Нумерованный список
│   ├── <имя>JSON.json             # Структурированный формат JSON
│   ├── <имя>YAML.json             # Формат YAML
│   ├── <имя>XML.json              # Формат XML
│   ├── <имя>Markdown.json         # Формат таблицы Markdown
│   ├── <имя>MarkdownKV.json       # Формат пар ключ-значение Markdown
│   └── <имя>DSL.json              # Пользовательский формат DSL
└── <директория результатов>/      # Содержит .test-set-part → "results" (создаётся во время выполнения)
    └── .test-set-part
```

### Форматы тестирования

| Формат | Описание |
|------|------|
| Оригинал (Plain Text) | Обычный текст повествовательного характера, как базовое сравнение |
| Список (List) | Нумерованный или маркированный список |
| JSON | Стандартный объект JSON |
| YAML | Структурированные данные YAML |
| XML | Иерархическое представление тегами XML |
| Markdown | Таблица Markdown |
| MarkdownKV | Пары ключ-значение Markdown |
| DSL | Пользовательский предметно-ориентированный язык |

## Основные функции

- **Визуальный редактор холста** — SVG-холст с узлами, комбинирование промпт × вопрос × модель перетаскиванием, поддержка рисования соединительных линий
- **Отмена/Повтор** — Полная система истории, поддержка Ctrl+Z / Ctrl+Shift+Z
- **Сравнительное тестирование форматов** — Одно и то же содержимое в 8 форматах, оценка различий в понимании модели для каждого формата
- **Пакетное автоматическое тестирование** — Декартово произведение комбинаций промпт × вопрос × модель, автоматическое параллельное выполнение
- **Управление несколькими моделями** — Управление моделями через всплывающее окно, поддержка добавления/удаления/сортировки
- **Настройка рассуждения** — Независимая конфигурация параметров thinking/reasoning_effort для каждой модели
- **Переключатель отключения параметров** — Каждый параметр можно независимо включить/отключить через dot-toggle
- **Потоковый вывод в реальном времени** —推送 потоковых результатов на основе SSE, ход теста виден в реальном времени
- **Просмотр истории** — Поиск и фильтрация исторических результатов по статусу/модели/тексту
- **Архивация/Восстановление** — Сохранение/загрузка снимков конфигурации теста (включая состояние холста + конфигурацию рассуждения модели)
- **Обнаружение модели _notFound** — Холст автоматически обнаруживает недоступные модели и отображает предупреждение ⚠
- **Автоматическое добавление /v1** — Переключатель для автоматического добавления `/v1` к адресу API
- **Тёмная/светлая тема** — Полная система CSS-переменных для переключения тем
- **Поддержка Anthropic API** — Поддержка формата сообщений Anthropic + специальный парсинг SSE для рассуждений
- **Многократное тестирование** — Один вопрос можно повторять несколько раз для измерения стабильности ответов
- **Контроль параллелизма** — Настраиваемое количество параллельных потоков и стратегия повторных попыток
- **Инкрементальное сохранение** — Периодическое инкрементальное сохранение результатов во время теста для предотвращения случайной потери
- **Проверка безопасности путей** — Защита от path traversal-атак, проверка зарезервированных имён Windows, белый список имён файлов

## API Интерфейс

| Эндпоинт | Метод | Описание |
|------|------|------|
| `/` | GET | Предоставляет фронтенд SPA |
| `/api/v1/config` | GET/POST | Чтение/сохранение конфигурации |
| `/api/v1/models` | GET/POST | Получение списка доступных моделей/сохранение списка моделей |
| `/api/v1/test-set/scan` | GET | Сканирование тестовых наборов |
| `/api/v1/test-set/prompts` | GET | Получение системных промптов тестового набора |
| `/api/v1/test-set/questions` | GET | Получение вопросов тестового набора |
| `/api/v1/test-set/results` | GET | Получение исторических результатов тестов |
| `/api/v1/test-job/hub` | POST | Единое планирование задач (action: start/status/stop) |
| `/api/v1/test-job/stream/<job_id>` | GET | Потоковая передача результатов SSE в реальном времени |
| `/api/v1/canvas-state` | GET/POST | Сохранение/чтение состояния холста |
| `/api/v1/archives` | GET/POST/DELETE | Управление архивами |
| `/api/v1/tags` | GET | Получение всех тегов |

Ответ об ошибке: `404` → `{"error": "Not found"}`, `500` → `{"error": "Внутренняя ошибка сервера"}`

## OpenCode Skills

Этот проект включает два инструментальных навыка, помогающих быстро создавать тестовые наборы и управлять ими:

### Пользовательские инструменты (`skills/`)

Сценарии и документы, которые разработчики могут запускать напрямую:

| Файл | Описание |
|------|------|
| `skills/New-TestSet-新建测试集.ps1` | PowerShell-скрипт, автоматически создающий пронумерованный скелет тестового набора с директориями и маркерными файлами .test-set-part |
| `skills/QA-Extract-问答提取.md` | Подробное руководство по извлечению пар вопрос-ответ из исходных файлов и генерации совместимых JSON-файлов |

### Навыки AI Agent (`.opencode/skills/`)

Если вы используете [opencode](https://opencode.ai) или совместимые инструменты кодирования ИИ, навыки из `.opencode/skills/` могут быть автоматически обнаружены и загружены AI Agent:

| Навык | Описание |
|------|------|
| `new-test-set` | Инструктирует ИИ создать скелет тестового набора (директории + маркерные файлы) с автоматической нумерацией для избежания конфликтов |
| `qa-extract` | Инструктирует ИИ извлечь пары вопрос-ответ из исходных файлов и вывести JSON, совместимый с форматом тестового набора FormTest |

## Технический стек

- **Бэкенд**: Python Flask + Flask-CORS
- **Фронтенд**: Нативный HTML / CSS (пользовательская система переменных, тёмная/светлая тема) / JavaScript
- **Вызовы ИИ**: Библиотека `requests` (поддержка потокового SSE и обычного JSON-режима, совместимость с OpenAI / Anthropic API)
- **Параллелизм**: Пул потоков `ThreadPoolExecutor` + повторные попытки с экспоненциальной задержкой
- **Вывод**: Server-Sent Events (`text/event-stream`)
